# ADR-0004：固定服务名称，仅配置 HTTP Base Path

- 状态：已接受
- 日期：2026-08-15

## 背景

OpsKeeper 需要部署在根路径或反向代理的子路径下，但服务名称、日志标识和镜像内二进制名称如果也由通用前缀动态拼接，会增加构建、探针、监控和运维文档的组合复杂度。

## 候选方案

1. 使用一个通用前缀同时动态生成服务名、二进制名和 HTTP 路径。
2. 分别配置每个服务名、二进制名和 HTTP 路径。
3. 固定产品服务名和二进制名，只允许配置 HTTP Base Path。

## 决定

采用方案 3。服务名和镜像内二进制固定为：

```text
opskeeper-api
opskeeper-worker
opskeeper-scheduler
opskeeper-migrate
```

`OPSK_BASE_PATH` 只控制 API、健康检查、静态资源和页面的 HTTP 路径前缀，默认 `/opskeeper`，支持 `/` 和多段子路径。构建过程不提供二进制名前缀变量。

## 影响

- 日志、探针、部署清单和运维手册可以依赖稳定名称。
- 同一集群部署多个实例时，通过 Namespace、Release 名和工作负载资源名区分，而不是改写进程内部服务名。
- 前端构建和运行时必须正确处理可配置 Base Path。
- 产品如果未来需要白标或多产品二进制，需要新增 ADR 重新评估，而不是恢复一个隐式通用前缀。
