# ADR-0005 本地身份与不透明会话基线

## 状态

已接受，T03 实施中

## 背景

T02 的组织 API 没有身份确认能力。T03 需要提供首个管理员初始化、密码验证、登录、刷新、注销和用户停用后的会话失效，同时不能把密码或会话 Token 写入数据库、日志或 API JSON 响应。当前阶段不实现角色、Scope 继承和用户管理授权。

## 决策

1. 用户和凭据属于 `identity` 特性包；`users`、`credentials` 和 `sessions` 由同一个身份迁移创建。
2. 密码使用 Argon2id 编码存储，编码中保存参数和随机盐；验证接受受限参数范围，成功登录时可升级到当前参数。
3. 登录产生独立的短期访问 Token 和长期刷新 Token，数据库只保存两者的 SHA-256 摘要。
4. 刷新在单条数据库更新中轮换访问和刷新摘要；同一个刷新 Token 的并发请求只有一个成功，旧 Token 不能重放。
5. 浏览器使用 HttpOnly、Secure（生产强制）和 SameSite=Lax Cookie；非浏览器客户端可使用响应 Cookie 或 Bearer 访问 Token。Token 不出现在 JSON 响应中。
6. 首个管理员只能通过 `make admin-create` 的受控命令创建，公开 HTTP 不提供 bootstrap 端点；数据库 advisory lock 保证并发初始化只有一个成功。
7. 认证中间件只确认用户身份并检查用户状态，T03 不判断角色或 Scope 权限。组织业务 API 在启用身份服务时要求身份确认。

## 后果

- 用户停用或锁定不需要主动遍历会话表；每次访问和刷新都联结检查用户状态，因此已有会话立即失效。
- 会话摘要泄露时不能直接用于认证，但数据库和应用日志仍需按敏感数据边界保护。
- Cookie 方案适合当前同源嵌入式前端；跨站客户端、CSRF 防护增强和企业 SSO 留待后续任务评估。
- T04 必须在身份中间件之后增加授权中间件，不得把角色判断混入本次身份实现。
