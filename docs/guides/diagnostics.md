# 诊断指南

## 1. 诊断过程

诊断按“问题 → 核验目标 → 工具观察 → 更新判断 → 继续调查或结论”循环执行。主 Agent 统一规划、审阅和总结；Subagent 只是一次独立调查任务，最多一级，不能递归创建任务。

协同度是会话级偏好，默认值为 2（谨慎协同）。即使协同度较高，简单问题或有依赖顺序的问题也可保持串行。每轮启动时记录实际协同度；主 Agent 审阅结果后可以继续下一轮工具调用或创建新的一级调查任务。

## 2. 证据边界

结果必须区分：

- **事实**：用户提供的信息或工具返回的日志、指标、配置、代码和状态。
- **推断**：由事实支持的可能原因，必须说明依据和置信度。
- **未检查范围**：权限拒绝、超时、截断、资源不可用或尚未调查的分支。

Subagent 返回证据、来源、时间、目标对象、工具、任务状态和边界，不返回面向用户的最终答案。主 Agent 负责处理冲突、去重、补充调查和最终回答。共享资源只有在实际对象定位和调查目标一致时才能复用证据。

## 3. 调查任务

每个任务至少包含：

```text
目标、应用/实例/资源、对象定位、专家能力、拆分理由、预期信息
```

服务端必须重新校验 Scope、资源关联、权限、内部 ID 防护、取消、超时和证据预算。模型提出的任务不是授权凭证。

平台硬限制包括单轮任务数和同时执行数；达到上限、预算不足或任务失败时，主 Agent 应退回串行调查或明确说明未执行范围。

## 4. 回答结构

简单问题直接回答。一般问题按需要给出结论、关键证据、建议和未检查范围。复杂问题使用：

```text
现象 → 证据 → 判断 → 建议 → 风险/未检查范围
```

不展示隐藏思维链，不把工具调用过程冒充最终结论。没有 Evidence 的内容只能作为待验证假设。

## 5. 诊断页面和 API

诊断页面展示当前轮次的进度、工具调用、观察结果和证据引用；追问会创建新轮次，不覆盖旧结论。精选因果链只引用同一会话的 Evidence，默认关系为：

```text
原因 → 作用机制 → 现象/结果
```

相关接口：

```text
POST /api/v1/diagnosis-sessions
GET  /api/v1/diagnosis-sessions/{id}
GET  /api/v1/diagnosis-sessions/{id}/events
```

完整 API 和前端事件契约见 [design/ai-engine.md](../design/ai-engine.md)；当前项目的资源工具边界见 [integrations.md](integrations.md)。
