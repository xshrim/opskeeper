# OpsKeeper 分阶段实施任务书

## 1. 文档目的

本文将 OpsKeeper 的建设过程拆分为 13 个可独立审批、实施和验收的任务。任务按依赖关系顺序执行，后续任务默认依赖所有前置任务已经验收通过。

本文只定义实施计划，不代表任何任务已经获得实施授权。

## 2. 执行与审批规则

1. 所有任务初始状态为 `待批准`。
2. 每个任务开始前，实施方需汇报目标、范围、关键决策、风险和预计文件变更，并取得用户明确批准。
3. 未获得当前任务批准时，不创建代码、不安装依赖、不执行数据库变更，也不提前实施后续任务。
4. 当前任务出现超出本文范围的设计变更时，暂停实施并重新申请批准。
5. 当前任务完成后，需提交变更摘要、验证命令、验证结果、遗留问题和下一任务说明。
6. 只有当前任务验收完成后，才申请下一个任务；批准一个任务不代表批准后续任务。
7. 文档修订不自动改变任何任务的审批状态。

状态定义：`待批准`、`实施中`、`待验收`、`已完成`、`阻塞`。

## 3. 目标工程结构

工程初始化后预计采用以下目录结构，实际创建须在任务 1 获批后进行：

```text
opskeeper/
├── backend/
│   ├── cmd/api/
│   ├── cmd/worker/
│   ├── cmd/scheduler/
│   ├── internal/
│   ├── migrations/
│   └── tests/
├── frontend/
│   ├── src/lib/
│   ├── src/routes/
│   └── tests/
├── deploy/
│   ├── compose/
│   └── helm/
├── docs/
└── Makefile
```

后端首版使用模块化单体。模块可以有独立的领域、服务、仓储和 HTTP 层，但共享进程和数据库；只有 API、Worker、Scheduler 分为独立运行单元。

## T01 工程初始化与质量基线

**状态：已完成**

验收记录：[T01 工程初始化与质量基线验收记录](t01-acceptance.md)

### 目标

建立可重复启动、测试和检查的前后端分离工程，为后续业务功能提供稳定基础。本任务不实现任何组织、权限或资源业务。

### 实施细节

1. 初始化 Go Module，创建 `api`、`worker`、`scheduler` 三个入口及共享 `internal` 包。
2. 建立配置加载规范，支持环境变量和本地配置样例，禁止提交真实密钥。
3. 建立结构化日志、请求 ID、Recover、统一错误结构和 `/health/live`、`/health/ready`。
4. 初始化 Svelte 5、TypeScript、Vite，建立路由、API Client、基础布局和错误边界。
5. 在 `deploy/compose` 提供 PostgreSQL、Redis 本地环境及健康检查。
6. 提供 Makefile 命令，包括启动、格式化、静态检查、单元测试和数据库服务管理。
7. 增加 Go 和前端的最小单元测试，建立 `.editorconfig`、忽略规则和环境变量样例。
8. 固定主要依赖版本并记录本地开发前置条件。

### 预计文件范围

`backend/`、`frontend/`、`deploy/compose/`、`Makefile`、`.editorconfig`、`.gitignore`、配置样例和开发说明。

### 验收标准

- Go API、Worker、Scheduler 和 Svelte 开发服务均能启动。
- API 存活及就绪检查返回结构化结果。
- PostgreSQL 和 Redis 连通性能够进入就绪检查。
- 后端测试、前端测试、格式化和静态检查全部通过。
- 仓库中不存在真实凭据或与机器绑定的绝对配置。

### 不包含

数据库业务表、登录、RBAC、资源 CRUD、Kubernetes 接入和实际业务页面。

### 实施前待确认

- 当前目录不是有效 Git 工作区，本任务默认不初始化或修复 `.git`。
- 默认使用现有环境可支持的稳定 Go、Node.js 和包管理器版本，实施前报告实际检测结果。

## T02 PostgreSQL 与三级 Scope/组织模型

**状态：已完成，依赖 T01（已完成）**

验收记录：[T02 Scope 与组织模型验收记录](t02-acceptance.md)

### 目标

实现统一 Scope 树以及平台、团队、项目组织模型，形成所有资源和权限的归属基础。

### 实施细节

1. 建立迁移框架和迁移执行命令，所有 Schema 变更可前滚和回滚。
2. 创建 `scopes`、`platforms`、`teams`、`projects` 表及状态、时间和软删除字段。
3. 使用数据库约束保证 Platform 无父节点、Team 父节点为 Platform、Project 父节点为 Team。
4. 建立团队编码平台内唯一、项目编码团队内唯一等索引。
5. 实现事务化 Repository 和 Service，组织与 Scope 必须在同一事务创建或变更。
6. 提供团队和项目的创建、查询、修改、停用及分页 API。
7. 初始化单个平台根 Scope；不开放创建多个平台的业务接口。
8. 对父子关系、唯一性、软删除、并发创建和非法迁移编写集成测试。

### 预计文件范围

`backend/migrations/`、`backend/internal/scope/`、`backend/internal/organization/`、HTTP 路由、数据库测试工具。

### 验收标准

- 能创建团队和项目并得到正确的三层 Scope 路径。
- 非法父子层级、重复编码和孤立组织均被数据库或服务层拒绝。
- 停用上级组织时能阻止新建下级对象，并保留历史数据。
- 迁移在空数据库可重复执行，组织模块测试通过。

### 不包含

用户登录、角色授权、资源模型和前端管理页面。

## T03 身份认证与三级 RBAC

**状态：待批准，依赖 T02**

### 目标

实现用户身份、内置角色、Scope 继承授权和服务端数据范围校验。

### 实施细节

1. 创建用户、用户组、组成员、角色、权限、角色权限和角色绑定表。
2. 内置 PlatformAdmin/Operator/Viewer、TeamAdmin/Operator/Viewer、ProjectAdmin/Operator/Viewer。
3. 实现短期访问会话、刷新与注销；密码使用 Argon2id，Cookie 使用 HttpOnly、Secure 和 SameSite 策略。
4. 提供认证中间件和 `Authorize(subject, permission, targetScope)` 授权服务。
5. 实现平台向团队/项目、团队向项目的权限继承，以及多个有效角色权限并集。
6. 实现防越权授权：授权人不能授予自身不具备的权限或超出自身 Scope。
7. 将 Scope 过滤直接注入查询层，验证通过 ID 访问和列表查询都不会泄露越权数据。
8. 提供用户、成员和角色绑定管理 API，并记录安全审计基础事件。
9. 建立认证、继承、跨团队隔离、权限缓存失效和越权测试。

### 预计文件范围

认证和授权迁移、`backend/internal/identity/`、`backend/internal/authorization/`、HTTP 中间件和安全测试。

### 验收标准

- 用户可登录、刷新和注销，失效会话不能继续访问。
- 平台、团队、项目三级角色按设计继承且不跨团队泄露。
- `resource:read`、`resource:use` 和管理权限能够独立判定。
- 管理员不能通过授权接口完成权限提升。
- 权限相关测试覆盖正向和反向场景。

### 不包含

企业 OIDC/LDAP 单点登录、细粒度显式拒绝策略和 PostgreSQL RLS。默认先实现本地身份，实施审批时可改为优先接入指定 SSO。

## T04 统一资源目录、凭据和关系模型

**状态：待批准，依赖 T03**

### 目标

实现任意资源类型可归属平台、团队或项目的统一资源目录，以及符合 Scope 规则的资源关系。

### 实施细节

1. 创建资源、资源 Schema、凭据密文、资源关系、同步状态和 Scope 默认配置表。
2. 资源只引用 `scope_id`，由 Scope 节点确定平台、团队或项目层级。
3. 使用版本化 JSON Schema 校验不同 `kind` 的 `config`，首批注册架构设计中的资源类型。
4. Credential 资源保存元数据，密文使用信封加密接口存储；开发环境提供本地密钥实现。
5. 实现资源 CRUD、标签过滤、分页、连接状态和软删除。
6. 实现关系创建、查询和删除，严格校验“同 Scope 或向上引用”规则。
7. 使用递归 CTE 提供有限深度的上下游拓扑查询，并限制节点数量。
8. 实现显式默认解析规则：项目默认优先于团队默认，团队默认优先于平台默认。
9. 增加密钥脱敏、跨团队关系、非法向下依赖、循环和迁移影响测试。

### 预计文件范围

资源迁移、`backend/internal/resource/`、`backend/internal/credential/`、拓扑查询和相关 API。

### 验收标准

- 同一种资源可分别创建在平台、团队和项目 Scope。
- 项目能引用所属团队及平台资源，但不能引用其他项目或团队资源。
- API 永不返回凭据明文，日志中不出现敏感值。
- 拓扑查询遵守用户权限和最大深度限制。
- 资源移动 Scope 前能检测并拒绝失效关系。

### 不包含

具体资源连接器、Kubernetes 自动发现和资源管理前端。

## T05 Svelte 管理控制台基础功能

**状态：待批准，依赖 T04**

### 目标

提供可实际操作三级组织和资源模型的管理控制台，并正确体现当前作用域和用户权限。

### 实施细节

1. 实现登录、会话恢复、注销和未授权跳转。
2. 建立平台、团队、项目三级导航和稳定的 Scope 切换器。
3. 实现平台总览、团队列表、项目列表和成员/角色绑定页面。
4. 实现资源列表、详情、创建/编辑表单、标签、状态和作用域标识。
5. 根据资源 JSON Schema 生成或选择类型化表单，不允许直接编辑敏感字段。
6. 实现资源关系编辑器和基础拓扑视图，限制图节点数量并支持按关系过滤。
7. 按后端返回的有效权限隐藏或禁用操作，但所有安全判断仍由后端完成。
8. 建立加载、空数据、错误、无权限和长文本等完整界面状态。
9. 增加关键组件测试和 Playwright 端到端流程测试。

### 预计文件范围

`frontend/src/routes/`、`frontend/src/lib/api/`、组件、状态管理、样式和前端测试。

### 验收标准

- 用户可完成登录、作用域切换、团队/项目查看和资源管理。
- 不同角色只看到允许的导航和操作，后端拒绝伪造请求。
- 资源名称始终带有明确作用域，避免同名资源误用。
- 桌面和移动视口无内容重叠，关键端到端用例通过。

### 不包含

Kubernetes 导入向导、AI 对话和巡检页面。

## T06 Kubernetes 集群发现与项目导入

**状态：待批准，依赖 T05**

### 目标

允许用户添加任意 Scope 的 Kubernetes 集群，预览 Namespace 和工作负载，并按集群作用域安全导入项目资源。

### 实施细节

1. 注册 KubernetesCluster、Namespace、Node、Workload、Pod、Service 和 Ingress Schema。
2. 使用 `client-go` 建立集群连接、TLS 校验、只读权限检查和客户端缓存。
3. 创建发现运行、发现项和导入结果表，Worker 异步执行扫描。
4. 扫描 Namespace 并可配置排除系统命名空间，生成新建项目、映射项目或忽略建议。
5. 平台集群必须选择目标团队；团队集群只能映射本团队项目；项目集群只能导入当前项目。
6. 集群、Node、Namespace 保持集群 Scope，Workload、Pod、Service 和 Ingress 归属映射项目。
7. 使用 Kubernetes UID 和来源集群形成幂等键，支持重复同步和差异预览。
8. 根据 ownerReference、selector、Service 和 Ingress 建立确定关系；配置推断依赖只生成待确认候选。
9. 不读取 Kubernetes Secret 内容；删除对象先标记 `missing`，超过宽限期后归档。
10. 实现前端分步导入向导、进度展示、差异确认和同步历史。

### 预计文件范围

发现迁移、`backend/internal/discovery/`、Kubernetes Connector、Worker 任务和前端导入页面。

### 验收标准

- 三种 Scope 的集群都遵守各自导入边界。
- 用户确认前不创建项目或业务资源。
- 重复导入不产生重复资源，变更和删除能正确反映。
- 无权限、连接失败、大集群分页和中断恢复均有明确结果。
- 使用测试集群或模拟 API 完成端到端导入测试。

### 不包含

主动修改 Kubernetes 对象、日志采集和 AI 分析。

## T07 Connector 框架与外部监控平台

**状态：待批准，依赖 T06**

### 目标

建立统一外部能力接口，首批支持 Kubernetes、Prometheus 和 Loki，为 Skill 提供受控数据访问。

### 实施细节

1. 定义 Connector 生命周期、能力声明、连接测试、超时、重试、限流和错误分类。
2. 定义 `query_metrics`、`query_logs`、`query_traces` 和 `get_alerts` 结构化能力接口。
3. 实现 Connector 注册表，根据资源 `kind` 和版本选择适配器。
4. 完成 Kubernetes 查询能力，并实现 Prometheus HTTP API 和 Loki HTTP API 适配器。
5. 对查询时间范围、步长、日志条数、最大响应体和并发量设置硬限制。
6. 统一附加来源资源、采集时间、查询窗口和原始响应摘要，形成证据候选。
7. 实现连接测试 API 和资源详情中的连接状态展示。
8. 使用模拟服务测试超时、分页、限流、错误响应、部分数据和敏感信息脱敏。

### 预计文件范围

`backend/internal/connector/`、Prometheus/Loki/Kubernetes 适配器、资源连接测试 API 和对应前端状态。

### 验收标准

- 上层只依赖能力接口即可查询不同外部平台。
- 项目可以同时关联平台级 Prometheus 和团队级 Loki。
- 所有查询都经过权限、范围、限流和输出大小校验。
- Connector 错误可区分配置、权限、超时、限流和上游故障。

### 不包含

Tempo/Jaeger/Elastic 实现、AI 诊断编排和自动巡检。

## T08 LLM Provider、Skill 注册表与受控 Runner

**状态：待批准，依赖 T07**

### 目标

建立可配置的大模型接入、版本化 Skill 管理以及不绕过权限的 Skill 执行环境。

### 实施细节

1. 注册 LLMProvider、Model、Skill 和 MCPServer 资源 Schema。
2. 建立 LLM Provider 接口，首版实现 OpenAI-compatible Chat/Tool Calling 适配器。
3. 实现模型能力、上下文窗口、Token 价格、超时和 Scope 默认模型配置。
4. 创建 Skill 和 SkillVersion 表，保存 Manifest、输入/输出 Schema、工具、风险等级和状态。
5. 实现 Skill 发布、停用、版本固定、适用资源检查和配置校验。
6. 实现 Runner：参数校验、目标授权、工具白名单、超时、取消、输出限制和执行记录。
7. LLM 不能直接访问 Connector，所有外部访问必须通过 Runner 暴露的结构化 Tool。
8. 增加模型连接测试、Token 用量统计和输入输出脱敏。
9. 使用模拟 LLM 和 Connector 验证 Tool Calling、错误恢复和越权阻断。

### 预计文件范围

AI/Skill 迁移、`backend/internal/llm/`、`backend/internal/skill/`、Runner、Provider/Skill 管理 API 和基础页面。

### 验收标准

- 平台、团队、项目均可创建相应 Scope 的 Provider 或 Skill。
- 项目能按显式绑定及项目 > 团队 > 平台顺序解析默认模型和 Skill。
- Runner 能拒绝未声明工具、无权资源、非法参数和超时调用。
- 每次执行都固定 Skill 和模型版本并记录用量。

### 不包含

完整诊断会话、内置中间件 Skill、MCP 调用和自定义代码执行。

## T09 AI 诊断编排、证据链与对话工作台

**状态：待批准，依赖 T08**

### 目标

实现以项目和目标资源为上下文的流式诊断流程，使结论能够追溯到工具调用和原始证据。

### 实施细节

1. 创建诊断会话、消息、诊断计划、工具调用、证据、假设和报告表。
2. 会话绑定起始 Scope 和目标资源，新增目标时重新鉴权。
3. AI Orchestrator 构建目标资源、可见上级资源、依赖拓扑、近期状态和历史证据上下文。
4. 实现计划、执行、验证和归纳阶段，并限制最大步骤、最大 Tool 调用和 Token 预算。
5. 工具返回统一转换为带来源、查询窗口、采集时间和哈希的 Evidence。
6. 最终结论必须引用证据 ID；无充分证据时标记为待验证假设。
7. 将外部日志、注解和 MCP 文本标记为不可信输入，隔离其中的指令性内容。
8. 通过 SSE 推送计划、阶段、工具状态、证据和最终报告，并支持断线续传。
9. 实现诊断工作台、资源选择、时间线、证据抽屉和会话历史。
10. 使用固定模拟数据评估证据引用、权限隔离、重复执行和模型异常场景。

### 预计文件范围

诊断迁移、`backend/internal/diagnosis/`、AI Orchestrator、SSE、诊断前端页面和测试数据集。

### 验收标准

- 用户可从项目或资源发起流式诊断并继续追问。
- 每个确定性结论都能跳转到证据及其来源。
- 模型无法请求用户无权访问的资源或未授权工具。
- 刷新或断线后能恢复会话和已持久化事件。
- 诊断失败不会留下永久运行状态或泄露模型原始敏感内容。

### 不包含

写操作、MCP、自定义 Skill 代码和定期巡检。

## T10 Kubernetes 与中间件内置 Skill

**状态：待批准，依赖 T09**

### 目标

提供可投入实际只读诊断的内置 Skill，覆盖 Kubernetes、PostgreSQL、Redis 和 Kafka 常见故障。

### 实施细节

1. 实现 Kubernetes Workload、Pod、事件、调度、探针、资源限制和发布状态 Skill。
2. 实现 PostgreSQL 连接、活跃会话、慢查询、锁、复制和容量 Skill。
3. 实现 Redis 连接、内存、热 Key、慢命令、客户端和复制状态 Skill。
4. 实现 Kafka Broker、Topic、分区、ISR、消费组和积压 Skill。
5. 每个 Skill 定义所需资源类型、Connector 能力、只读权限、超时和结构化结果。
6. 数据库和中间件账号使用最小只读权限，明确记录所需授权清单。
7. 将确定性规则与模型解释分离：规则产生事实和异常，模型负责关联与说明。

9. 使用容器化测试实例、故障夹具和黄金结果验证常见场景。

### 预计文件范围

- 输出包含事实、异常、证据、假设、置信度和建议。

- Skill 测试覆盖至少一组正常状态和主要异常状态。

### 不包含

自动重启、扩缩容、写 SQL 或参数修改。

## T11 自动巡检、健康评分和通知

**状态：待批准，依赖 T10**

### 目标

允许平台、团队和项目创建周期巡检策略，可靠执行确定性检查和 AI 分析，并形成可去重的异常与通知。

### 实施细节

1. 创建巡检策略、运行、步骤、Finding、健康快照、通知渠道和投递记录表。
2. 支持 Cron、时区、维护窗口、目标/标签选择器、Skill 集、超时、重试、并发和预算。
3. Scheduler 使用 PostgreSQL advisory lock 生成任务，Job Queue 使用租约、心跳和幂等键。
4. Worker 在运行开始时冻结目标和拓扑快照，避免执行期间配置漂移。
5. 先执行确定性检查，只在异常解释和关联阶段按策略调用 LLM。
6. 健康评分由规则和权重计算，LLM 不直接修改评分。
7. Finding 使用目标、规则和时间窗口生成指纹，实现去重、持续、恢复和重新打开。
8. 首版实现 Webhook 通知，支持重试、签名、限流和投递记录。
9. 实现策略编辑、运行历史、健康趋势、异常详情和手动重跑页面。
10. 测试重复调度、Worker 崩溃、超时、维护窗口、预算耗尽和通知失败。

### 预计文件范围

巡检迁移、`backend/internal/inspection/`、Scheduler、Worker Job、通知模块和巡检前端页面。

### 验收标准

- 三级 Scope 策略只能选择自身有权覆盖的目标。
- 同一调度窗口不会生成重复报告或重复通知。
- Worker 中断后任务可重新获得租约并安全恢复。
- 健康评分可解释，Finding 生命周期和通知记录完整。
- LLM 不可用时确定性巡检仍能完成并明确降级。

### 不包含

邮件/短信等更多通知渠道、容量预测和自动变更。

## T12 MCP、自定义 Skill 沙箱与高风险操作审批

**状态：待批准，依赖 T11**

### 目标

在明确安全边界下扩展 MCP 和自定义 Skill，并为可能改变生产状态的操作建立人工审批闭环。

### 实施细节

1. 实现 MCP Server 连接、能力发现、版本快照、健康检查和 Tool 白名单。
2. 对 MCP 请求实施 Scope 权限、网络出口、超时、响应大小和内容不可信标记。
3. 自定义声明式 Skill 继续使用 Runner；需要执行代码的 Skill 运行在独立 Kubernetes Job 沙箱。
4. 沙箱默认只读文件系统、非 root、资源配额、最小 ServiceAccount、禁用特权和受限网络出口。
5. 创建操作请求、审批策略、审批记录和执行结果表。
6. 按 ReadOnly、Low、Medium、High 风险分级；Medium 及以上默认要求人工审批。
7. 审批时展示精确目标、参数、影响范围、有效期和回滚建议，参数变化后审批自动失效。
8. 对重启、扩缩容等首批有限操作实现 dry-run 和幂等执行；高危删除及写 SQL 默认仍禁用。
9. 测试 Prompt Injection、MCP 恶意响应、沙箱逃逸基础配置、审批重放和参数篡改。

### 预计文件范围

MCP/审批迁移、`backend/internal/mcp/`、沙箱执行器、Policy Enforcement、审批页面和安全测试。

### 验收标准

- MCP Tool 不能突破调用用户和目标 Scope 权限。
- 自定义代码不能直接运行在 API 或 Worker 主进程中。
- 未批准、过期或参数变更的操作不能执行。
- 所有操作请求、审批、执行和结果均可审计。

### 不包含

无人值守高风险处置和任意生产脚本执行。

任务：Txx 任务名称
