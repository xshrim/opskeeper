# I002-R001 控制台体验与高频工作流优化

**迭代：** I002-ui-function-optimization
**需求状态：** 实施中
**验收报告：** `R001-requirement-acceptance.md`

## 1. 需求背景

I001 已覆盖控制台的大部分平台能力，但当前前端将多个复杂工作流集中在单一页面中，页面反馈、列表检索、长任务恢复和窄屏使用体验仍不一致。用户需要在不同模块重复理解状态、手动确认刷新结果，异常时也缺少明确的下一步动作。

## 2. 目标

- 让用户在任意页面都能识别当前作用域、页面状态和下一步动作；
- 缩短概览到资源、诊断和待处理审批的路径；
- 让长任务断线、失败和重复提交有安全且可恢复的行为；
- 在不改变既有 API 安全边界的前提下，提升列表检索和表单操作效率；
- 通过自动化测试固定关键交互，降低后续迭代回归风险。

## 3. 范围

- 登录页面、应用壳、侧边导航、顶栏、作用域选择器和全局通知；
- 概览健康摘要、待处理事项和快捷入口；
- 组织/资源列表的搜索、筛选、状态提示和详情返回；
- Kubernetes 发现预览与导入的选择、映射、进度和失败恢复；
- 诊断、巡检、通知和操作审批的执行状态、重试、取消/返回和结果查看；
- 桌面/窄屏响应式布局、键盘操作、语义标签和可见焦点；
- 单元、组件和 Playwright 端到端测试。

## 4. 非目标

- 不修改认证、RBAC、Scope 数据隔离、审计和受控操作审批规则；
- 不新增数据库迁移或外部连接器能力，除非为现有交互修复 API 契约缺陷并单独记录；
- 不在本需求中实现 OI-006 的 Markdown Skill 编辑器和 Tool Catalog；
- 不以视觉改版为由删除现有功能或降低错误信息和审计信息的可见性。

## 6. 任务说明

### T01 登录页面优化

#### 目标

将现有登录页重构为现代、克制、直觉化的产品入口，并以确认方案的色彩、排版、间距、控件和反馈方式作为本轮后续页面的统一视觉基准。

#### 实施范围

- 桌面端采用大背景图与右侧登录区，左上角固定展示 OpsKeeper Logo 和平台名称；
- 使用真实或生成的运维基础设施位图，图像需清晰、可裁切且与 Kubernetes/运维场景直接相关；
- 登录区包含账号、密码、密码显隐、校验错误、提交 Loading、登录失败和服务状态；
- 不增加当前后端不支持的注册、找回密码或第三方登录入口；
- 窄屏改为顶部背景图、下方登录区，保留品牌首屏信号且无页面级横向滚动；
- 先评审以下五种方案，确认前不实施最终页面。

#### 固定设计约束

- 全局最多使用一种中性色和一种品牌高亮色，背景为纯白或 `#F8FAFC`，禁止渐变和装饰光斑；
- 右侧登录区是独立页面区域，不使用卡片套卡片或重阴影；
- 表单宽度控制在 `360-400px`，输入框提供示例 Placeholder，错误就地说明纠正方式；
- 页面进入后焦点落在账号输入框，Tab 顺序为账号、密码、密码显隐、登录按钮；
- 提交后按钮立即进入 Loading 并禁止重复提交，失败提示保留输入内容和重试入口；
- 背景图提供响应式裁切和深浅对比保护，Logo、名称与文字在所有视口清晰可读。

#### 五种候选方案

五种候选方案如下；用户已在评审中确认定稿方向。

| 方案 | 视觉语言 | 桌面布局 | 交互与响应式 | 取舍 |
|---|---|---|---|---|
| A 冷静控制台 | 石墨黑 `#171B21` + 青柠 `#B8D84A`；深色数据中心或值守大屏照片 | 图像占 64%，右侧 `440px` 纯白登录面板；Logo 位于图像左上，表单垂直居中 | 登录状态集中在按钮和表单顶部；移动端图片占首屏 30%，表单紧随其后 | 品牌识别强、运维感明确；暗图需要严格控制可读性 |
| B 明亮基础设施 | 深蓝灰 `#233044` + 青色 `#0EA5A8`；明亮机房或云基础设施照片 | 66/34 硬分栏，右侧微灰背景不加边框；表单靠上三分之一，底部显示服务状态 | 字段逐项校验，服务异常时在按钮上方给重试入口；移动端图像缩为顶部横幅 | 清爽、亲和、企业感强；图片需避免普通图库感 |
| C 沉浸式侧舱 | 炭黑 `#20242A` + 琥珀 `#F5B942`；全屏运维中心照片 | 图片铺满视口，右侧 `420px` 不透明白色侧舱覆盖其上；Logo 独立悬于左上 | 面板从右侧轻微淡入，禁止大幅位移动画；移动端侧舱转为下方完整白色区域 | 最现代、沉浸感最强；对图片质量和裁切要求最高 |
| D 精密分界 | 墨蓝 `#182433` + 亮蓝 `#2563EB`；Kubernetes 集群或服务器阵列近景 | 图像占 58%，右侧占 42%；两区以 1px 分割线连接，表单左对齐并留出宽阔右边距 | 密码显隐、Caps Lock 提示和错误信息均原位出现；移动端隐藏非关键状态信息 | 信息清晰、密度舒适、实现稳定；视觉冲击弱于沉浸式方案 |
| E 运维态势栏 | 灰黑 `#1F2933` + 绿色 `#16A36A`；带真实监控屏的运维工作台照片 | 图像占 70%，右侧窄栏 `400px`；表单居中，底部固定显示 API/PostgreSQL/Redis 汇总状态 | 服务状态可展开查看但不抢占登录主流程；移动端只保留一行汇总状态 | 兼顾登录与系统可用性感知；需避免登录页信息过载 |

#### 已确认设计

2026-08-18，用户确认使用根目录 `background.jpeg` 作为登录背景，并采用“暖白悬浮侧栏”定稿方向。该设计作为 T01 的视觉基准，后续页面沿用以下令牌和交互基线：

- 背景：全屏覆盖，桌面端保持主体构图，窄屏使用响应式裁切；Vite 资源副本为 `frontend/src/assets/login-background.jpeg`；
- 品牌：左上角橙色 Logo 方标，旁边两行显示 `OpsKeeper`（23px）和 `智能值守平台`（12px）；
- 登录区：右侧 `410px` 白色悬浮面板，8px 圆角、细暖灰边框和柔和阴影；窄屏转为顶部品牌、下方完整面板；
- 色彩：深灰文字 `#2F2926`、橙色主操作 `#E7601B`、暖白表面 `#FFFFFF`、背景辅助色 `#EEE8E5`；
- 交互：账号/密码占位符、密码显隐、提交 Loading、禁用原因、错误提示、键盘焦点和移动端无横向溢出。

#### 验收标准

- 用户已从五种方案中确认一种，并记录选择理由与冻结的设计令牌；
- 桌面端满足“大背景图 + 右侧登录 + 左上角 Logo/名称”，窄屏完成对应重排；
- 登录成功、失败、字段非法、服务异常和提交中状态均有明确反馈；
- 键盘可完成全部登录操作，焦点清晰，错误可被辅助技术读取；
- 背景图片完成压缩与响应式加载，不阻塞表单首次可交互；
- Playwright 覆盖桌面、窄屏、成功登录、失败重试和重复提交保护。

#### 风险和回滚

背景图片可能影响首屏性能和文字对比度；实施时保留当前登录流程与 API 契约，只替换页面结构和样式。若视觉资源加载失败，页面降级为纯色背景且表单保持可用。

### T02 概览与作用域导航优化

#### 目标

让用户进入控制台后快速知道系统健康度、当前作用域和需要处理的事项。

#### 实施范围

优化健康状态摘要、资源统计、巡检发现、待审批操作和最近诊断入口；作用域切换后明确展示继承关系、数据刷新状态和当前上下文。

#### 验收标准

- 首屏能区分健康、告警、未知和数据尚未加载；
- 概览中的待处理事项可直接进入对应详情视图；
- 切换作用域不会展示旧作用域数据，失败时给出重试入口；
- 桌面和窄屏首屏均无横向溢出。

#### 风险和回滚

概览聚合请求可能增加首屏等待；保留已有独立接口和降级展示，必要时回退为现有摘要布局。

### T03 资源与发现工作流优化

#### 目标

降低资源查找、查看详情和 Kubernetes 导入的操作成本。

#### 实施范围

增加资源列表的可见搜索/筛选/排序状态和清除路径，改善详情返回后的上下文保持；优化发现预览的选择、项目映射、导入进度、部分失败和重试反馈。

#### 验收标准

- 搜索、筛选和排序组合可见且可清除，结果状态明确；
- 详情返回后保留列表作用域和筛选条件；
- 发现导入展示总数、已处理数、成功数和失败项，失败项可定位并重试；
- 无权限或能力缺失时不显示误导性的可操作控件。

#### 风险和回滚

列表状态管理复杂度上升；优先复用现有 API 分页契约，若后端不支持新筛选则采用前端受控降级并记录后续 API 需求。

### T04 诊断巡检与审批工作流优化

#### 目标

使长任务和高风险操作的状态、结果及恢复路径清晰可控。

#### 实施范围

优化 SSE 诊断事件展示、断线后的状态恢复、巡检运行与发现查看、通知配置反馈，以及操作审批的风险提示、重复提交保护和结果/快照入口。

#### 验收标准

- 诊断连接断开后可恢复或明确失败，不重复创建会话；
- 巡检和操作请求展示进行中、成功、失败、拒绝和超时状态；
- 高风险操作在提交前显示目标、影响和审批状态，重复点击不会重复创建请求；
- 结果查看和返回路径不丢失当前作用域。

#### 风险和回滚

事件流时序和后端状态可能不一致；以服务端状态为准，前端只允许幂等刷新和安全重试，异常时回退到只读结果查看。

### T05 响应式与可访问性完善

#### 目标

保证常用控制台流程在窄屏和键盘操作下可完成。

#### 实施范围

检查 320px、768px 和桌面视口，修复横向溢出、固定宽度控件、表格和弹层布局；补充语义标题、表单标签、键盘焦点和状态播报。

#### 验收标准

- 关键页面在 320px 宽度下无页面级横向滚动；
- 所有核心操作可仅用键盘完成，焦点顺序和可见焦点合理；
- 表单控件具有关联标签，异步状态变化可被读取；
- 颜色对比和状态表达满足既有前端可访问性检查约束。

#### 风险和回滚

响应式规则可能引发桌面回归；采用视口矩阵截图和现有 E2E 流程逐页验证，问题可按页面回退。

### T06 自动化测试与性能验收

#### 目标

用可重复证据证明优化没有破坏既有能力，并控制首屏与交互开销。

#### 实施范围

补充 Svelte 单元测试和 Playwright 场景，覆盖登录、作用域切换、资源筛选、导入失败恢复、诊断断线、审批重复提交和窄屏布局；记录前端构建、检查和质量门禁结果。

#### 验收标准

- 新增场景在 CI 和本地可重复运行；
- `npm run check`、`npm run test`、`npm run build` 和 `npm run test:e2e` 通过；
- 关键视图没有新增明显的首屏阻塞或无界轮询；
- 验收报告记录命令、环境、结果和遗留问题。

#### 风险和回滚

E2E 依赖服务可能造成不稳定；测试数据和路由桩保持隔离，环境问题单独标记，不以跳过测试替代验收。

## 7. 需求级验收标准

1. 关键页面具备一致且可操作的加载、空数据、错误、重试和成功状态。
2. 概览、资源、发现、诊断、巡检和审批流程可在桌面与窄屏视口完成，且不改变权限与审计边界。
3. 长任务断线、失败、超时和重复提交均有安全的恢复或明确的只读降级路径。
4. 键盘、焦点、语义标签和状态播报通过对应自动化检查。
5. 前端检查、单元测试、构建和 Playwright 验收全部通过，并有可复核证据。
